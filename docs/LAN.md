# 满载而鼠 · 局域网联机 v0.3.5-lan5

## 开始联机

两台电脑使用本版，连接同一 Wi-Fi / 路由器。每台电脑一个玩家，各有独立画面；同队合作或红蓝对战，空位由 AI 补齐。

1. 打开主菜单的“局域网联机”，选择昵称、队伍、形象与武器。
2. 房主选择地图，点击“创建房间”。
3. 另一位玩家在“附近房间”选择房主的房间，点击“直接加入”。列表显示人数、地图、可加入 / 已满 / 对局中 / 版本不同。
4. 双方点击“准备”，房主点击“开始对局”。

找不到房间时，可以填写房主的局域网 IP 和端口，点击“加入房间”。默认游戏端口 UDP 28765，自动发现使用 UDP 28766。允许游戏访问本地网络；访客 Wi-Fi 的设备隔离会阻止联机。

## 自动重连

短暂断线时，会显示自动重连倒计时，最多等待 30 秒。房主继续运行对局，断线玩家停止移动和射击，仍可受伤。网络恢复后自动回到原来角色，恢复主机当前的位置、生命、弹药、成长和胜负状态，无需重新开局。

重连绑定随机凭据，不以昵称识别玩家。重新开始一局会更换凭据。恢复时清空旧输入预测、插值缓存和特效队列，再接收当前完整状态。超过等待时间会结束连接并返回大厅。房主关闭游戏后不能迁移主机；需要重新建房。

加载过程中断线仍需重新建房；重连只支持已开始的对局。保持游戏进程打开，关闭游戏后重新启动不会恢复上一局。

房主可从暂停或结算界面“返回房间”，双方重新准备后开始下一局。客户端暂停菜单不会暂停主机战斗。

## 同步

主机模拟 60Hz 战斗；客户端上传控制，接收 20Hz 压缩状态。移动、瞄准与翻滚使用独立预测，其他角色使用时间缓冲。生命、弹药、伤害、升级及道具仍由主机裁决。HUD 显示延迟、状态流量、缺帧和缓冲。

## 丢包恢复与回收优化

每四个 900 字节状态分片增加一个异或恢复分片，每组丢失一个原始分片时可恢复；原始分片和恢复分片可能乱序到达。每组同时缺两个分片时继续等后续状态，不编造战斗结果。状态仍不重传，最多保存三个未完成快照。

这会增加状态流量，完整地图采样中载荷增加约 27%；小包和最后一组不满四片时比例可能更高。两台电脑都必须升级本版，旧版会显示版本不同。

实体永久移出时会断开目标、燃烧归属、宠物和箱子刷新点等引用；复用世界前先清理上一局。这修复了已复现的循环引用残留，长时间进程内存仍需实测。

## 弱网稳定性优化

状态包持续丢失时，特效事件最多缓存 64 批、8192 个；单批上限 1024 个。收到新状态后只补播最近半秒的事件，避免旧枪声、爆炸和受击特效集中出现。生命、弹药、成长和胜负始终由状态快照恢复。

入房握手必须在 8 秒内完成，超时的连接释放位置。地图、版本变化会立即刷新附近房间；异常动作和搜房数据会被忽略。重连尝试再次断开时会释放旧连接继续重试。

## 验证

```bash
tools/test.sh
python3 tools/test_lan_resume.py
```

真实 ENet 双进程验证：两次重连、第二局、过期和无效身份、版本不匹配、主机尚未记录断开时的身份恢复、完整 Main / MatchView / HUD 流程。UDP 代理模拟单程 25～75ms 延迟与 2% 随机数据报丢失。新增未注册连接回收、异常动作 RPC 和两分钟完整地图弱网回归。持续测试使用单程 25～100ms、4% 随机丢包，加入 1.2 秒和 10 秒中断，并检查特效缓存上限与自动续局。测试代理为每个客户端端口保留独立回包路径。测试扫描通过真实 UDP 回环查询，跨电脑的 Wi-Fi 广播发现仍待实测。

目前为两台电脑局域网联机，不含公网连接、超过两人、房主迁移或混合本地分屏。Mac / Windows 包导出通过；跨系统真机联机和目标 GPU 性能待实测。

## v0.3.6-lan6：输入与大厅恢复修复

- 客机重连期间房主返回房间时，客机收到房间信息后结束旧局恢复、清理旧状态，双方可重新准备下一局。
- 可靠动作携带按下瞬间的方向、瞄准与输入序号。冲刺固定使用该次按下的方向；较新的输入可补回丢失的移动包，较旧的动作不会覆盖已收到的新移动输入。客户端预测重放也保留冲刺方向。
- 持续输入超时停止移动和射击，但不清除刚收到的可靠动作；离开或断线时仍清除全部输入。
- 客机地图选项随房主房间信息刷新；离线选图保留玩家自己的选择。
- 无可接收队友时跳过网络快照编码并清除旧特效；每批待发送临时特效先限制至 1024 个，再编码发送。生命、伤害、成长及胜负仍由快照负责。
- 协议升级到 5，兼容签名加入应用版本。双方须同时更新本版。

新回归包含：重连中返回大厅、真实 Main/MatchView 第二局、两种动作/方向到达顺序、5000 个特效突发的发送上限、地图显示更新。

持续弱网回归还定位到新旧连接交替时的无效通道发送错误。本模式采用主机权威拓扑，现关闭 `SceneMultiplayer.server_relay`，发送及注册应答前确认连接有效、通道仍存在。所有业务消息仍在客机与房主之间传输。
